# 额外内容总纲与实施计划：工业 / 魔法

> 2026-11-22 制定；基线：**Tiderift Beta Build 50**。
> 性质：总纲 + 分阶段计划，**本轮只规划，不实施功能、不升版本、不发布**。
> 关联：`docs/worldview.md`、`docs/TODO.md`、`docs/agent-notes/multiplayer.md`、`docs/agent-notes/world-ledger.md`。
> 建议节奏：以当前 BUILD=50 为基准，规划 **Build 51–56**；若正式开工时版本已前进，编号整体顺延，开工前重新核对代码与远端状态。

---

## 一、目标与结论

### 1.1 用户目标

新增世界创建前的可选模块“额外内容”，提供单独界面，首批包含两个彼此独立的内容：

- **工业**：机械动力、加工、物流与有限自动化。
- **魔法**：以四界潮汐来历为依据的回响能力、焦点与探索。
- 两者可以分别启用，也可同时启用；同时启用后出现少量联动，但联动不构成第三个模块。

### 1.2 本计划拍板的设计结论

1. **默认全部关闭**。旧存档、旧房间以及未配置的新世界均保持原体验。
2. **世界创建时决定，创建后不可更改**。它是世界规则，不是可随时切换的视频/游戏设置。
3. **四种组合都完整可玩**：无额外内容、仅工业、仅魔法、工业+魔法。任一单模块都不借另一模块的物品、机器或法术补足自己的主闭环。
4. **注册与启用分离**。方块、物品、配方和生物定义始终按固定顺序注册；开关只决定生成、获取、放置、交互与模拟是否启用。绝不按开关条件注册，避免数字 ID 漂移。
5. **工业采用“潮压机械”**，不用现代电网/RF 的换皮。首版动力来自燃料与桶装水，不做依赖自然水流的免费水车。
6. **魔法采用“四潮回响”**，不是第五种元素，也不新立神明。法术不改地形、不创造流体、不改时间、不造传送门、不跨维瞬移。
7. **工业与魔法先做各自的最小闭环，再分别扩展，最后做联动**。不为联动反向污染两条独立 成长线。
8. **全关基线必须可证明不变**：同种子、同群系规模下，地形与既有结构、旧战利品和运行行为与 Build 50 保持一致；性能上不得引入常驻工业扫描或魔法 HUD 工作。

### 1.3 不做什么

- 不做通用 Mod 加载器、脚本包市场、第三方内容下载或运行时热插拔。
- 不做“进入世界后打开/关闭工业或魔法”的热开关，也不提供管理面板热改。
- 不做第三个“联动内容”开关；联动只在两个开关同时打开时启用。
- 不用工业替代红石，不用魔法替代信标、鞘翅、末影珍珠或既有终局奖励。
- 不做 NPC 对话、任务树、过场动画，不改写“一潮三分”与“潮归其位”的既定历史。
- 首版不做水车、风车、矿场 quarry、流体管道、自动建造、附魔台体系、自由法术编辑器或新维度。

## 二、现状诊断与架构含义

以下均为对 Build 50 代码的核对结果，不是假设。

### 2.1 世界创建链目前没有“世界内容清单”

- `src/ui/MenuScreen.js` 的单人页和 LAN 页共用模式、种子、群系规模等草稿状态；点击空槽或创建房间即开始。
- `src/main.js` 通过位置参数调用 `Game.start()`；`src/player/Game.js` 当前签名为
  `start(mode, seed, loadData, slot, cheatsEnabled, networkMode, biomeScale)`。
- `Game.start()` 创建 `World` 时只传 `{ biomeScale }`。换维时 `_composeSwitchLoadData()` 重新合成数据，必须显式透传任何新的世界规则。
- `src/workers/TerrainWorker.js` 的生成器缓存键目前只有 `seed + biomeScale`。若额外内容影响生成而不扩键，同种子不同模块组合会错误复用生成器。

**含义**：需要一份规范化、不可变、可随世界重建传递的“世界内容清单”，而不是再往现有调用链末尾零散追加布尔值。

### 2.2 单人存档与导入导出需要显式接入

- `src/core/SaveSystem.js` 的 SAVE_VERSION=2；旧字段可缺省回落，无需仅为新增可选字段强升存档版本。
- `listSaves()`、保存、加载与换维合成都是独立接入点，漏一个就会出现“保存后开关丢失”或“换维后内容变化”。
- `src/core/SaveTransfer.js` 会保留未知字段，但已知世界选项是显式净化的；导入摘要也不知道额外内容。

**含义**：世界清单必须进入保存、列表摘要、导入净化、导入摘要、换维合成五条路径；旧档缺字段统一解释为双关。

### 2.3 LAN 已有合适的固定世界参数通道，但不能复用热配置

- `server/room.js` 的 `seed`、`biomeScale` 都是“首次创建固定，重复创建不可覆盖”，语义与额外内容完全一致。
- `WORLD_INFO` 在创建、加入、重连、重建时下发，是客户端取得房间权威清单的正确通道。
- `server/store.js` 的房间快照尚无额外内容字段；旧快照必须双关回落。
- `config.roomSettings` 的 PvP、mobs 是管理面板可热改规则，**不适合**存放创建后不可变的世界清单。
- 加入不存在的房间会自动创建；游戏内 `/room` 切到不存在房间也会创建。这两条隐式创建路径必须明确清单来源，不能静默双关。

**含义**：把清单放在房间根状态与快照中，和 seed/biomeScale 同生命周期；不要塞进 `roomSettings`。

### 2.4 内容注册与展示目前都是全局的

- `BlockRegistry` / `ItemRegistry` 在模块加载时一次性注册，方块数字 ID 由顺序决定；新内容只能尾部追加。
- `Crafting.js` 的全局配方表没有调用上下文；创造物品栏直接遍历两个 Registry；RecipeViewer 也展示全量配方。
- 结构类型在 `src/world/structures/catalog.js` 全局注册，`StructureManager` 再按维度过滤。
- 战利品、自然生成、命令面板、创造栏各自都有可能绕过“仅 UI 隐藏”的开关。

**含义**：必须有统一的内容归属元数据与显式世界上下文过滤，并覆盖获取、放置、生成、交互和网络消息，不能只隐藏创造栏图标。

### 2.5 工业与魔法应复用不同的既有权威模型

- B36 已有 `flowSweep`、服务器权威熔炉、维度账本、客户端联机早退和权威回滚，适合作为工业机器的模板。
- 箭矢/凋灵之首已有“事件广播 + 发起端结算怪物 + 远端纯视觉”的模型，可作为魔法弹道的参考。
- 房间服务器没有完整的自然世界方块查询能力，主要持有修改账本。依赖“旁边是否为天然流动水”的免费动力若直接交给服务器，会产生权威缺口。
- 单机与联机玩家档案目前由客户端上报，服务器清洗与持久化；项目不是竞争性反作弊服务器。

**含义**：工业生产归服务器固定节拍；魔法个人资源沿用项目的轻信任模型，服务器把关模块、施法频率、消息负载和维度，但不宣称实现强反作弊。

## 三、世界规则与界面总纲

### 3.1 世界内容清单

建议持久化形态：

```json
{
  "extraContent": {
    "schema": 1,
    "industry": false,
    "magic": false
  }
}
```

规则：

- 只认 `schema===1` 与两个严格 boolean；旧档/旧快照缺字段回退上述默认值。遇到未知或更新的 schema 必须拒绝加载/加入并提示版本不兼容，不能静默降级成双关而丢失内容规则。
- `schema` 用于以后迁移世界规则，不与 BUILD、SAVE_VERSION、PROTOCOL_VERSION 混用。
- 世界运行时只保留一份规范化结果；UI 草稿、网络缓存、Worker 缓存键均从它派生。
- 创建后不可通过暂停菜单、命令、管理 API、重复 create_room 或旧客户端覆盖。

### 3.2 四种组合的行为矩阵

| 工业 | 魔法 | 世界行为 |
|---|---|---|
| 关 | 关 | Build 50 原始内容；新内容不可自然生成、合成、放置、施放或 tick |
| 开 | 关 | 完整工业闭环；魔法与联动不出现；不需要任何魔法物品 |
| 关 | 开 | 完整魔法闭环；工业与联动不出现；不需要任何工业机器 |
| 开 | 开 | 两条独立闭环 + 少量联动；联动仍不是通关或主 成长线 的强制条件 |

“关闭”不是从存档中删除已经存在的数据：若异常导入或人为篡改带入禁用内容，保留其方块/物品数据，不替换成空气；但不得继续生产、施放、提供新获取路径或运行模块机制。

### 3.3 单独界面

新增共享的 `ExtraContentScreen` 规划，入口分别位于：

- 单人页的“新建游戏设置”区，点击空槽前打开；
- LAN 页的创建/加入区，在可能创建新房间前打开。

界面要素：

1. 标题“额外内容”及说明“仅在创建新世界时确定；已有世界不受影响，创建后不可更改”。
2. **工业**、**魔法**两张独立卡片：名称、短描述、主要内容、独立开关，不互相嵌套。
3. 两张卡片均开启时才显示联动说明；不显示第三颗开关。
4. “全部关闭”恢复原始体验，“完成”返回来源页；新建摘要再次列出已启用的模块。
5. 草稿只在本次菜单会话中保留；读取旧存档时绝不采用当前草稿。
6. 存档槽、导入摘要和 LAN 房间信息以徽标显示“工业 / 魔法”；暂停菜单只允许查看，不允许修改。

不建议把入口放在主菜单作为全局默认设置：额外内容属于某个新世界，不属于所有世界的永久偏好。

### 3.4 新建、加入、切换与重建的口径

- 单人新建：使用确认后的草稿；读档：只信存档。
- LAN 创建房间：仅首次创建采用建房者清单；重复创建同名房间沿用旧值。
- LAN 加入：随请求携带“若目标不存在时的创建草稿”，目标已存在则完全忽略本地草稿。
- 游戏内 `/room` 创建新房间：继承当前房间的额外内容，避免绕过创建前界面；界面提示这一点。正式开工时可把“隐式新建是否继续允许”列为小评审，但不得无提示双关。
- 断线恢复到已不存在的房间：不得借恢复包改清单；中止恢复并回创建流程，不自动造出另一套规则的世界。
- `/rebuild`：只重置地形与运行账本，保留当前房间清单。要更改模块只能明确创建新世界/新房间。

### 3.5 新旧客户端能力协商

纯新增字段本身不必升 PROTOCOL_VERSION，但旧客户端不能安全进入含有未知方块/物品的世界：

- HELLO 增加客户端支持的额外内容 ID 与 schema 能力。
- 新服务器只对**启用了客户端不支持内容的房间**拒绝加入，给出升级提示。
- 旧客户端仍可进入双关房间；新客户端本地草稿是否开启不影响其加入能力。
- 新协议消息按项目惯例可纯新增；若改变既有字段语义，再单独升 PROTOCOL_VERSION，不能把“加清单”当作绕过兼容审查的理由。

## 四、共同技术总纲

### 4.1 单一来源与显式上下文

规划新增纯模块 `src/content/ExtraContent.js`，负责：

- 清单常量、规范化、相等比较、稳定序列化；
- 内容 ID：`industry`、`magic`；
- 查询定义所需模块，例如 `requiredExtras(def)`；
- 判断某方块、物品、配方、生物、结构或能力是否对当前世界启用；
- 给 Worker、服务器与测试复用，不依赖 DOM。

方块/物品定义可增加白名单元数据 `requiresExtras`；联动定义为 `['industry','magic']`，不伪造第三个内容 ID。

**禁止**用一个可随意读写的全局“当前世界开关”供所有模块隐式消费。世界上下文必须显式传入生成器、配方匹配、tick 与服务器房间，防止 Worker、测试和跨存档串状态。

### 4.2 世界启动参数收口

建议把 `Game.start()` 的选项收敛为一个选项对象，而不是继续增加第 8、第 9 个位置参数：

- 新建/读档/联机/换维共用 `biomeScale` 与 `extraContent` 的解析；
- `World` 构造接收并保存规范化清单；
- `_composeSwitchLoadData()` 显式透传；
- 所有调用点在同一里程碑迁移，并用现有 Game 行为回归防止改坏网络模式、作弊与 biomeScale。

### 4.3 注册、获取与使用五道闸

| 闸口 | 必须覆盖的路径 |
|---|---|
| 注册 | 所有内容始终注册并尾部追加；只附加归属，不按开关增删 |
| 获取 | 创造栏、搜索、RecipeViewer、配方实际匹配、战利品、交易、怪物掉落、命令面板 |
| 放置/交互 | 单机交互与放置、服务器 BLOCK_SET 与 BLOCK_SET_BATCH、机器界面、焦点施放 |
| 生成 | 结构、矿石/装饰、自然生物、Worker 与同步路径、查询/游记/命令定位 |
| 模拟/网络 | 工业 tick、魔法 cast、服务器消息路由、重连与快照恢复 |

隐藏 UI 不是安全边界；服务器必须拒绝禁用模块的写入与施法，并回滚必要的本地预测。

### 4.4 确定性与旧随机流保护

- 新结构使用独立 salt 与独立 RNG 流，绝不插入既有结构或地形 RNG 消耗序列。
- `StructureManager` 在维度过滤的同一中心点再做 `requiresExtras` 过滤，且所有查询入口共用，避免“世界没生成，游记/命令却能找到”。
- 旧战利品表不改权重、不插条目。额外内容需要进入旧箱时，使用独立附表与独立 salt 的后置奖励 roll；双关时完全不执行。
- 新生物优先生成在独立模块 spawn pass，不重排原有 choices，避免即使关闭也改变旧生物分布。
- Worker 请求、生成器缓存键都包含规范化清单；同步与 Worker 必须逐字节一致。
- 全关时建立 Build 50 的固定种子基线夹具，不能用新实现自己反推自己当 oracle。

### 4.5 生命周期与性能

- 双关：不创建工业网络、不运行工业 sweep 的有效工作、不创建魔法 HUD/施法状态，只有轻量判断。
- 工业拓扑只在方块变化时标脏重建；不得每帧全图 BFS。
- 魔法粒子复用池，焦点/HUD/监听器随 `_disposeWorld()` 成对释放。
- 新方块纹理沿用 SVG 图集，图标统一 `BlockIcon.drawIconInto()`；不为机器创造第二套图标链。
- 新 UI 遵循 `controls.enabled`、输入互斥、i18n ×10 与跨存档清理纪律。

## 五、工业总纲：裂潮后的“潮工”

### 5.1 世界观定位

工业是雨民在旧炉、断轴与潮闸遗物上重新发展起来的**潮工**：利用燃料、热、水与机械传动，把零散营地变成能持续生产的工坊。

- 它来自对既有世界遗物的学习，不出现现代电网、芯片、核能或塑料。
- 红石仍是信号与控制；潮压是做功。两者职责不同，不把工业写成“更好的红石”。
- 下界潮火之炉提供热工启示，天域风阵提供机械结构启示，但不要求玩家先完成终局。
- 叙事仍由机器形制、遗迹、蓝图、物品 lore 与碑文承载，不新增 NPC 讲解。

### 5.2 核心循环

采集铁、铜、燃料与水桶 → 建造潮压锅炉 → 用传动轴连接加工机 → 用漏斗/箱子组织输入输出 → 用红石离合控制生产 → 扩展到分拣与作物收割 → 探索潮工遗迹、获得新加工与建筑方案。

### 5.3 内容分层

| 层 | 候选内容 | 职责 |
|---|---|---|
| 动力 | **潮压锅炉** `tide_boiler` | 消耗燃料与桶装水产生潮压，返还空桶；不读取自然水流 |
| 传动 | **传动轴** `drive_shaft` | 六邻接组成有界机械网络；拆分、合并、回路均幂等 |
| 控制 | **离合闸** `clutch`、**压力表** `pressure_gauge` | 红石控制通断；查看供需、停转原因，不替代红石信号体系 |
| 基础加工 | **碎石机** `crusher` | 首版圆石→砾石、砾石→沙等；后续扩展矿物与副产物 |
| 木材加工 | **切割机** `sawmill` | 原木、木板、木棍等专用配方，形成第二条生产线 |
| 物流 | **分拣漏斗** `filter_hopper` | 在既有漏斗节拍上增加单过滤槽与明确路由，不做无限高速管道 |
| 自动化 | **收割机** `harvester` | 只收割前方成熟作物并写入相邻容器；不破坏任意方块 |
| 探索 | **潮工遗迹**与配套碑文/蓝图 | 提供机器来历、加工材料与建设灵感，不做必须刷取的唯一硬门槛 |

命名是规划候选；实施前按世界观纪律登记术语并完成 ×10 语言设计，代码 ID 不随显示名反复变动。

### 5.4 潮压规则

- 网络供给 = 所有在线锅炉的产出；需求 = 所有正在工作的机器需求。
- 供给不足时全网按同一效率降速；无供给不推进。首版不跨维连接、不无线传输。
- 首版**不储存能量、不积累欠账**：锅炉停了即停，重载/重启不追赶离线生产，避免“上线结算几千倍产物”。
- 拓扑由方块账本派生，不持久化；机器槽位与加工进度才持久化。
- 压力表显示供给、需求、效率与断路位置；不需要伪造复杂流体压力物理。

### 5.5 单机与联机权威

规划共享纯算法（网络推进、配方、槽位路由），两端复用：

- 单机：本地固定节拍调用同一算法。
- 联机：服务器按维度维护 `dimensionIndustry` 状态；客户端不本地生产，只提交内容槽并显示权威回执。
- 服务器使用独立工业 sweep 或明确的固定节拍调度，建议 200ms；dt 钳制，离线不追赶。
- 机器状态键 = 维度 + 坐标；方块被替换即清除对应状态并按权威槽位散落，禁止幽灵机器。
- 网络拓扑只在相关方块增删时标脏；超限拒绝放置并回滚，不静默截断网络。
- 内容槽变化即时广播；活动机器进度按约 500ms 节流；静置机器零消息。
- 高频状态只 `saveSoon()`，由既有世界落盘节拍持久化，不逐 tick 全量写盘。
- 漏斗接入使用统一槽位规则；玩家手动编辑与服务器生产之间的竞态按熔炉现有口径记录，不宣称完全无竞争。

初始设计预算（实施前用基准测试定稿）：单网络不超过 128 个节点、单房间不超过 512 个工业方块、每 tick 每台机器至多一次配方推进。超限必须有提示，不允许以“性能保护”为名悄悄复制或删除物品。

### 5.6 为什么首版不做水车/风车

自然水车需要服务器可靠知道周边天然水体、流动状态和修改账本之外的区块。当前房间并没有完整自然世界查询层。若让客户端上报动力，生产就会依赖各端视图并失去统一权威。

因此首版选择锅炉：**燃料与桶装水都是可入账物品，空桶返还也可验证**。水车、风车、流体泵只有在另行完成“服务器自然方块采样与区块生命周期”评审后才可加入，不在本六 Build 承诺范围内。

### 5.7 工业验收闭环

玩家不看文档也能完成：锅炉装燃料和水 → 传动轴亮起/机器有读数 → 碎石机处理一组材料 → 漏斗把产物送入箱子 → 拆掉锅炉后全网停止 → 重进世界无重复产物。

联机再加：两人同时打开机器不双份产出；中途一人拆轴、另一人取货不复制；服务器重启后槽位与进度一致。

## 六、魔法总纲：四界留下的“回响”

### 6.1 世界观定位

魔法不是另一套宇宙力量，而是裂潮后留在星髓、潮火、雨水与无潮边界中的**回响**。回响焦点让使用者短暂听见并复现这些记忆。

- 雨潮对应恢复与守护，坠潮对应热与爆发，风潮对应运动与托举，无潮对应距离与留白。
- 末地仍然“潮从未到达”；无潮系不是水魔法换色，而是对边界、距离和缺失的理解。
- 不创造第五界，不让玩家取代天穹之心，不解释末影龙留白，不复活云民/火民。
- 既有石碑、潮候、结构可成为叙事触点，但不改变它们的原奖励与原终局门控。

### 6.2 核心循环

探索四界并取得基础材料 → 建造回响仪台 → 制作不同焦点 → 用经验调谐回响 → 在移动、战斗与探索中消耗回响施放 → 寻找回响遗迹、接触更高阶纹样。

### 6.3 资源与焦点

- 玩家拥有个人**回响值**与上限；施法消耗，经验可在回响仪台兑换为回响。
- 允许极慢的脱战自然恢复作为防卡死兜底，但不能替代主动调谐；具体数值在平衡里程碑用实测确定。
- 不做研究点数树、不做法术熟练度刷级。能力由焦点与材料开放，避免额外长期账本。
- 每种焦点对应一个潮系，右键施放；后续可用蓄力区分基础/进阶，不建立复杂符文编程 UI。
- 回响值进入单机存档与 LAN 玩家档案；冷却、蓄力、弹道是运行态，换世界/死亡按明确规则清理。
- 魔法关闭时，旧档案中的回响字段可保留但不生效，不在 HUD 显示，不回复、不扣减。

### 6.4 四个基础方向

| 潮系 | 候选焦点 | 基础能力 | 明确边界 |
|---|---|---|---|
| 风潮 | `gale_focus` | **风步**：沿视线短距冲刺，蓄力后获得短暂缓降 | 使用碰撞/射线约束，不穿墙、不变成创造飞行 |
| 坠潮 | `ember_focus` | **烬矢**：直线灼热弹，蓄力提高有限伤害 | 不点燃地形、不炸方块；怪物伤害不重复结算 |
| 雨潮 | `rain_focus` | **回潮**：自我恢复并短暂获得防护 | 不超出生命上限，不生成水，不在创造/旁观刷资源 |
| 无潮 | `tideless_focus` | **折步**：向可见落点短距折跃 | 目的地已加载且有站立空间；不跨维、不无限隔空传送 |

进阶方向只作 B55 的设计入口：雨潮的短时潮幕、风潮的滑翔托举、坠潮的无地形破坏爆发、无潮的边界感知。进阶不得突破上表边界，具体效果在该 Build 开工前单独平衡，不在现在预支数值。

### 6.5 回响仪台与探索内容

- **回响仪台** `resonance_table`：焦点制作、经验调谐与配方查看；不是附魔台，不给既有工具随机附魔。
- **回响遗迹**：按维度采用不同材质和残缺纹样，通过环境叙事说明四种回响；奖励以焦点材料、蓝图与 lore 为主。
- 新遗迹使用独立生成盐，不移动村庄、要塞、潮冢、神殿等既有结构。
- RecipeViewer 增加“调谐/机器加工”类型时，必须复用同一配方数据，界面与实际扣料不得各写一份。

### 6.6 单机与联机权威

- 本机玩家：本地校验焦点、回响、冷却、生存状态与安全落点；成功后才扣回响。
- 服务器：检查魔法已启用、法术 ID/维度/数值合法、目标范围与施法频率；按玩家记录最小施法间隔，转发清洗后的事件。
- 远端玩家：接收事件后只播放施法与弹道表现，不再次扣回响、不重复结算伤害。
- 怪物：参照箭矢由施法端走既有伤害链；玩家互伤必须经过既有 PvP 闸门。
- 自我治疗、自我移动只作用于本人；不广播“别人强制替你回血/位移”。
- 服务器对频率与形状做硬约束，但回响与背包仍沿用项目的轻信任玩家档案模型；文档不得宣称能抵挡恶意改包刷资源。
- 所有弹道有寿命、数量与速率上限；粒子、声音和 HUD 只表现，不参与判定。

### 6.7 魔法验收闭环

制作仪台与焦点 → 调谐回响 → 风步不穿墙、烬矢只结算一次 → 回响不足/冷却时明确反馈 → 保存重进后回响恢复、冷却无异常残留 → 魔法关闭的另一个世界完全没有焦点配方、HUD 与施法能力。

四方向完成后，再逐一验证雨潮不过量治疗、无潮不跨维/不穿入实体/不落未加载区块。

## 七、联动总纲：只在“工业 + 魔法”世界出现

### 7.1 原则

- 联动内容是 `requiresExtras=['industry','magic']`，由两个开关共同决定，不新增选择项。
- 两条独立主线无需联动即可完成；联动只提高效率、可读性与合作分工。
- 不用“魔法直接无限发电”或“机器批量复制焦点”破坏两边资源经济。

### 7.2 首批建议

1. **刻纹压印机** `rune_press`：消耗潮压与调谐材料，自动完成原本可在回响仪台手动完成的焦点充能/纹样加工。它是便利与自动化，不解锁独占高阶法术。
2. **风压超载**：在工业+魔法世界，用风潮焦点对有界机械网络施放，消耗回响，短时间提高网络效率。服务器校验两个开关、目标网络、范围与冷却；超时不累积、不跨维、不无限叠加。
3. **联合读数**：压力表在双开世界同时显示超载剩余时间；不增加第三套 HUD。

### 7.3 联动验收

仅工业或仅魔法世界中，上述配方、交互和消息全部不可见/拒绝；双开世界中可完成“手工调谐 → 机器压印 → 风压超载 → 到时回落”，没有永久增益、重复扣料或跨端分叉。

**验收门槛**：玩家能通过环境理解四系差异；探索不移动既有结构、不改变旧箱保底；无“必须工业才能继续”的步骤。

- 把新过滤恢复成全量显示/全量 tick，测试必须能抓住，证明用例不是只测 happy path。
- 禁用模块后伪造 BLOCK_SET、容器写入、施法与联动消息，服务器必须拒绝；只验证按钮消失不算通过。
- 在单机切存档、联机换房、Worker 连续处理不同清单世界后，不得沿用上一个世界的规则。
- 服务器重启、玩家重连、机器拆毁与法术失败路径都检查物品/回响守恒。

### 9.3 浏览器与实机手测

- 四种组合各建一个世界：检查独立界面、槽位徽标、配方可见性与实际闭环。
- 读取旧档时修改草稿，确认旧世界规则不被覆盖；导入/导出后清单与内容一致。
- LAN 至少双会话：不同本地草稿加入同一房仍得到同一清单；旧能力客户端只在启用未知内容时被拒。
- 工业实搭生产链并拆轴/拆锅炉/拆机器；魔法用真实输入验证移动、焦点、冷却和弹道。
- 每个 Build 都执行 `node --check` 改动文件、聚焦测试、`npm run build`、`npm test`；需要画面的地方保留截图与种子/房间记录。
- 性能采用硬件无关指标与同环境对照：tick 时间、消息数、拓扑重建次数、对象/监听器残留；不把 WSL 软渲染 FPS 当真机结论。

### 9.4 总体验收口径

只有同时满足以下条件，整个“额外内容”项目才算完成：

1. 世界创建前有真正独立、清晰、双模块可分别选择的界面。
2. 四种组合都有正确且持久的世界规则，旧世界默认不变。
3. 工业与魔法各自形成完整生存闭环，联动只在双开生效。
4. 单机、LAN、重连、重启、换维、导入导出、Worker 均不会串规则或复制资源。
5. 世界观保持“一潮三分”的因果与留白，工业/魔法像这个世界原本就有的技术与回响，而不是外来模组拼贴。
6. 全量回归、i18n、构建、浏览器/联机手测、性能与资源释放全部通过，文档没有超前承诺。

## 十、红线清单

1. **不得按开关条件注册内容**；新方块/物品/状态变体一律尾部追加，旧 ID 不动。
2. **不得把额外内容放入热改 roomSettings**，不得让重复 create_room、旧客户端或管理 API 覆盖世界清单。
3. **不得牺牲全关兼容性**：旧地形、旧结构位置、旧战利品、旧生物分布与旧存档行为不得因“顺便重构”改变。
4. **不得让客户端在联机中本地推进工业生产**；服务器是物品与进度的唯一权威。
5. **不得离线追赶工业生产或无限累积能量/超载**；大步长有钳制，收益有上限。
6. **不得让魔法改地形、造水、改时间、造门、跨维瞬移或绕过 PvP/创造/旁观约束**。
7. **不得让独立主线依赖另一模块**；联动不得成为任何一边的必要解锁。
8. **不得只隐藏 UI 而不做实际匹配、放置、生成、服务器消息过滤**。
9. **不得引入隐式全局当前世界开关**；Worker、服务器、测试必须显式接收清单。
10. **不得新增无预算网络、无限弹道、逐帧全图扫描、每 tick 全量落盘或每对象独立材质**。
11. **不得为了赶 Build 牺牲 ×10 i18n、SVG/图标统一链接、生命周期清理和唯一 runner 纪律**。
12. 本轮只交付计划；未经用户后续明确开工，不修改上述任何游戏实现。
