按表中顺序串行推进，每轮单独形成可审查、可验证的变更。轮 1 解决持久化链路，但不能据此宣称重连和跨维度一致性已全部修复；该结论须等轮 2 验收。

本轮次编号独立于 B30 计划，不续用其轮 10 等编号。B30 文档中的阶段性决策保留在历史记录中；本计划不将“规划修复轮”解释为立即实施、发布或调整版本号的指令。后续交付遵循届时有效的仓库约定，不预先指定目标 Build。

## 二、所有轮次共用的实施与验收规则

1. 开工先核对当前源码与审查基准的差异，确认问题仍存在；若已被修复，补足证据后调整对应状态，不能机械套用旧行号。
2. 每项先补会在旧实现上失败的行为回归，再修产品代码。测试调用真实入口并观察账本、消息、世界状态或资源事件，源码字符串检查仅作补充。
3. 两侧测试分别复用 `tests/harness.mjs`、`server/test-lib.mjs`；共享假环境放 `tests/lib/`。优先扩展已有相关套件；确需新建时同步注册 `server/run-all-tests.sh`，禁止复制 runner 或在套件内新增 `process.exit`。
4. 每轮执行改动 JS/MJS 文件的 `node --check`、相关聚焦套件、`npm run build` 与完整 `npm test`，并完成本轮浏览器验收。套件清单和计数以实际输出为准，不以审计报告里的历史计数作为完成条件。
5. 全量脚本会删除 `server/world/` 和 `server/config.json`，且要求 3001 空闲。应在独立测试副本运行，使用独立运行时数据与配置；核对其执行根目录后再启动，不直接对含真实数据的工作目录跑批。浏览器用一次性房间及独立命名会话，保留原有服务与存档。
6. 每轮记录旧实现失败用例、修复后结果、完整跑批日志、浏览器观察及尚未覆盖的边界。内存假环境不能证明真实断网或 GPU 行为，缺任一必需证据时标为“实现完成，验收未完成”，不能标记整轮完成。

实施前按涉及范围阅读：轮 1 的 `agent-notes/world-ledger.md`、`agent-notes/multiplayer.md`；轮 2 的 `agent-notes/multiplayer.md`、`agent-notes/dimensions-portals.md`；轮 3 的 `agent-notes/multiplayer.md`、`agent-notes/dimensions-portals.md`；轮 4 的 `agent-notes/survival-items.md`、`agent-notes/dimensions-portals.md`、`agent-notes/rendering-lighting.md`。上述路径均相对 `docs/`。

## 三、轮 1：方块账本完整留存（B32-1、B32-2）

**修改范围**：`server/room.js` 的单条和批量写入；`src/net/NetworkManager.js` 的远端方块应用。核查 `server/store.js` 的快照/恢复、`World.applyModifications()` 与修改索引，只有实际存在缺口才扩展修改范围。

**步骤与约束**：

1. 单条和批量更新均保留 `id=0`，区分“坐标没有修改记录”和“该坐标已修改为空气”。挖掉容器时继续清除容器内容账本，不删除空气记录。
2. 远端方块通过 `World.setBlock` 写入本地修改账本，保留网格、光照、红石的现有更新链；同坐标远端新值覆盖本地旧值。维度桶与 `ModifiedBlocks` 区块索引同时保持一致。
3. 利用 `_applyingRemote` 阻止回环，并保证异常时恢复守卫，避免一次失败吞掉后续本地操作。单条、批量、首次回放均核查同一落地语义。

**自动化验收**：

- 天然方块挖掘后，单条与批量账本都显式含值 `0`；放置后再挖掘、重复挖掘仍正确。
- 经真实快照序列化与恢复、新玩家加入、换维回执，坐标仍为 `0`；测试须检查字段存在，不能只用真假判断。
- 对远端放置、挖掘、覆盖本地旧修改分别执行区块卸载和重载，格值与账本保持最新；至少覆盖区块边界与负坐标。
- 远端落地不产生单条或流体批量回环；随后一次本地修改仍正常上报。容器清理行为不回退。

**测试落点**：优先扩展 `tests/room-persist-replay.mjs`、`tests/world-mod-index.mjs`，按需在 `tests/` 增加调用真实 NetworkManager/World 的行为套件；持久化链复用现有 store 测试设施。

**浏览器验收**：两会话分别挖掘与放置；另一会话走远触发区块卸载后返回，第三会话新加入核对；一次性房间正常落盘并重启服务后再次核对。换维往返核对同一坐标。

**完成条件**：服务端内存 → 快照恢复 → 新加入回放 → 客户端账本 → 区块重载，整条链均保留空气与放置结果。历史上已删除且没有备份的空气记录无法由本修复推算恢复，需在交付说明写明。

**实施记录（2026-10-19）**：旧实现红测确认服务端单条/批量挖掘均不留账本项，快照恢复和新玩家回放随之丢失；客户端远端修改也未写 `modifiedBlocks`。修复后，服务端两种写入都保留 `id=0`，同时独立清理容器内容；远端落地写入本地账本，并用 `finally` 确保异常时复位回环守卫。

- 聚焦回归：`room-persist-replay` 33/33（含单条、批量、容器、JSON 快照、加入回放）；`net-block-ledger` 9/9（挖掘/放置、区块卸载重载、无回环）；`server/test-store.mjs` 17/17（磁盘往返保留 0）；`world-mod-index` 359/359。
- 检查：五个修改的 JS/MJS 文件 `node --check` 全过，跑批脚本 `bash -n` 通过；`npm run build` 成功（156 modules）。完整 `npm test` 在临时副本中 `RESULT: ALL PASS`，一次性测试数据未触碰当前服务数据。
- 浏览器：三组隔离会话进入一次性房间。主端将天然草方块改为空气并放置石头；第二端收到空气账本值 0 和石头值 1，卸载/重载区块后两格仍保持；第三端晚加入也回放得到相同两格。方块修改由浏览器 DevTools 调用 `World.setBlock` 驱动，以覆盖真实客户端世界钩子和联机传输；未用鼠标执行挖放输入。本轮一次性房间及玩家档案已清理。

## 四、轮 2：回放取消与异维度重连（B32-4、B32-3）

**修改范围**：`server/room.js`、`src/net/NetworkManager.js`；核查房间成员移除/切换入口、`Game.applyDimensionWorld()` 及重建串行链。仅在握手需要新增消息字段或确认消息时同步修改 `server/protocol.js` 和客户端解析；实施时明确是否需要协议版本调整。

### 步 1：回放绑定生命周期（B32-4）

- 固定回放所属房间实例、维度、玩家/连接身份和回放代次。每次恢复发送前检查身份仍有效，不能用发送时的 `player.dim` 给旧桶重新贴标签。
- 新回放、换维、换房、断线、世界重建及房间销毁均使旧任务失效；处理计时器收尾。维度切走再切回、同名房间删除后重建也不能让旧任务复活。
- 保留正常背压恢复时不丢项、每批不超过既有上限，以及读取账本现值避免旧快照覆盖实时更新的行为。

**验收**：用可控假连接暂停回放，逐项触发换维、换房、断线、再次回放、切走再切回、房间重建，再排空等待任务；失效任务不得再发包。正常背压对照组仍完整发送，消息维度与来源桶一致，期间实时改写的同格值不回退。

### 步 2：重连先恢复维度与权威状态（B32-3）

- 定义明确阶段：断线/待恢复 → 加入原房间 → 确认目标维度与账本 → 本地应用完成 → 恢复交互及状态上报。WebSocket 打开或收到 `WORLD_INFO` 本身不能代表世界已就绪。
- 重连维度以断线时当前世界为恢复目标；房间、世界维度、网络层维度和服务端玩家维度须一致。首次进入及主动换房仍按其既定主世界入口处理。
- 可以复用换维请求/回执，但须处理“目标就是主世界”时服务端同维早退的情况，不能让恢复流程一直等待不存在的确认。
- 同维度也要按服务端权威账本收敛，包含撤销本地已过时修改；检查容器、掉落物、远端玩家、待处理消息和流体批量队列的归属，旧连接/旧世界消息不得带入新状态。
- 保持重连位置与背包语义；明确已有玩家档案下发与断线前位置的应用顺序，避免误用普通传送门落点而传送玩家。恢复完成前门控世界修改、拾取和位置广播，恢复失败或再次断线不能误解锁。

**自动化验收**：主世界、下界、末地、天域分别断线并重连；目标维度与位置一致，修改只落入该维度桶，同维玩家可见、异维玩家不可见，掉落物及容器按维度恢复。补充连续断线、恢复期间换房/退出、延迟回执、服务器拒绝入房的取消分支，以及首次入房和普通换维的对照回归。

**测试落点**：`tests/room-persist-replay.mjs`、`server/test-dim.mjs`、`server/test-profile.mjs`，按需增加客户端恢复状态机的行为套件。

**浏览器验收**：至少在一个非主世界真实关闭连接或中断网络并恢复；同时观察客户端和服务端维度、位置、互见、容器/掉落物，恢复后挖一格核对落账维度。再覆盖主世界重连与非主世界再次断线。模拟发送探针只能作为自动化补充，不能替代真实断网验收。

**完成条件**：旧回放不跨世界继续发送；重连恢复具有明确完成信号，信号前不能写入错误维度，完成后客户端与服务端状态一致。

## 五、轮 3：物品内容与终局状态隔离（B32-5、B32-6）

### 步 1：掉落物完整序列化（B32-5）

**修改范围**：`server/room.js` 中实时生成、死亡掉落、入房回放、换维回放及归属锁拒绝补发路径；核查客户端接收与拾取数据传递链。

- 建立统一掉落物消息序列化出口，覆盖 `id`、位置、物品名、数量、维度、可选 `data`、初速、归属与剩余锁时长。所有发送路径按同一契约构造，剩余锁时长按发送时间计算。
- 保留既有 `sanitizeItemData` 校验与禁止盒中盒规则，不因统一出口放宽输入校验或向异维度广播。
- 用装有多槽不同物品、含空槽的潜影盒作样本，逐槽深比较：实时生成 → 新加入 → 换维回放 → 归属锁拒绝补发 → 最终拾取。补充快照恢复后的回放，以及无 `data` 普通掉落物对照。
- 拒绝拾取后服务端记录仍在，客户端背包回滚且重建实体内容不丢失；合法拾取后内容完整并且只获得一次。

**测试落点**：`server/test-idea2.mjs`、`server/test-stage10.mjs`、`server/test-dim.mjs`，纯内存回放测试按需加入 `tests/`。

### 步 2：终局缓存归属与清理（B32-6）

**修改范围**：`src/player/Game.js` 的 `start()`/`returnToMenu()`，以及 `src/net/NetworkManager.js` 的终局状态暂存入口。

- 将 `finaleInfo` 限定在对应联机会话/房间；退出与失效会话清理。单机新建和加载仅使用各自的存档状态。
- 保留 `WORLD_INFO` 先于 `start()` 到达的合法恢复链，不能简单在每次 `start()` 开头无条件清空缓存。换维重建和同房重连也应保留正确终局状态。
- 未通关房间切换、缺少终局字段的消息不得沿用上一房间缓存；过时连接回调不能重新写回已清空状态。

**自动化验收**：已通关联机房间 → 菜单 → 新建单机、加载未通关单机，两条路径的完成标记和祭坛坐标均不继承；再保存加载确认未持久化污染。对照验证已通关单机自身状态、联机先收消息后启动、换房到未通关房间、同房重连及换维恢复。

**测试落点**：`tests/game-behavior.mjs`、`tests/endgame-finale.mjs`，优先复用 `tests/lib/game-env.mjs`。

**浏览器验收与完成条件**：潜影盒经过晚加入与拒绝补发后实际拾取，检查内容；已通关联机退出后新建及加载单机，检查并保存重载。两项分别满足数据完整性和存档隔离，方可关闭本轮。

**实施记录（2026-10-19）**：

- B32-5：旧实现回归确认晚加入、换维、拒绝补发与快照恢复消息漏掉 `data`；客户端拾取还会先把剩余数量写回 `drop.count`，再记录回滚信息，导致拒绝时数量为 0。现在所有掉落发送路径使用同一序列化器，保留经校验的内容、维度、速度及剩余锁时长；客户端在变更实体前记录实际拾取数量和内容，拒绝回滚按物品内容匹配，避免误扣背包内另一只潜影盒。

### 步 2：世界资源释放与所有权（B32-8）

**修改范围**：`src/player/Game.js`、`src/render/ChunkMesh.js`；核查 `src/render/SVGTextures.js` 的缓存及所有图集使用方。

- 明确 builder 创建的三种共享材质归 builder 管理，世界图集由世界生命周期统一释放；同一图集被怪物、粒子等多个使用方引用时只释放一次。
- 先终止 Worker、移除依赖网格并释放使用方，再释放材质和图集、清除持有引用；退出、换维、再次启动重复经过清理时应幂等。

**测试落点**：`tests/leak-guards.mjs`、`tests/game-behavior.mjs`；新增共享支持代码放入 `tests/lib/`。

**浏览器验收**：先验证床跨维往返后的真实重生；资源方面先预热，再连续至少 5 次同规模世界进入/退出及换维，在一致渲染时点记录 `renderer.info.memory.textures`、`geometries` 和 `renderer.info.programs` 数量。比较相同阶段是否随轮数持续增长；缓存造成的稳定非零基线允许存在。保留渲染截图和控制台错误检查，确认水面、怪物、粒子及新世界材质仍正常。
