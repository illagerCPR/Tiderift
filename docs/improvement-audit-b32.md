# Tiderift 第二次项目审查报告（Build 32）

> 审查日期：2026-10-19 · 基准提交：`4a58acf`（Beta Build 32）
> 范围：联机账本、重连、换维度、跨存档状态及资源释放。
> 方法：源码与调用链核对、Node 内存探针、现有针对性回归套件。
> 结果：确认 8 项问题，高优先级 6 项、中优先级 2 项。
> 状态：仅分析留档，未修改产品代码，修复未实施。

## 一、高优先级

### B32-1：联机挖掘结果无法持久保存（P1）

- **位置：** `server/room.js:567`，`onBlockSet()`；批量路径 `onBlockSetBatch()` 同样存在。
- **原因：** 收到 `id=0` 时直接删除账本记录。确定性地形中，“没有修改记录”意味着使用原始地形，并不意味着空气。
- **影响：** 后来加入的玩家、重新进入维度的玩家会看到被挖掉的天然方块重新出现；服务器重启也无法恢复挖掘结果。
- **实证：** 对天然方块坐标发送挖掘更新后，服务端对应维度账本为空。
- **建议：** 保留值为 `0` 的修改记录；容器内容清理与方块空气记录分别处理。单条、批量、快照恢复与回放保持一致。
- **回归重点：** 挖掘天然方块后，新玩家加入、换维往返以及服务端快照恢复均保持空气。

### B32-2：远端方块修改在区块重载后消失（P1）

- **位置：** `src/net/NetworkManager.js:509`，`applyRemoteBlock()`；重载路径见 `src/core/World.js` 的 `applyModifications()`、`unloadChunk()`。
- **原因：** 远端更新使用 `world.setBlock(..., false)`，跳过本地修改账本。区块卸载后重新生成，只恢复原始地形和本地已记录的修改。
- **影响：** 走远再回来，其他玩家建造的方块可能消失，其他玩家挖掉的方块可能恢复，客户端与服务器逐渐分叉。
- **实证：** 同一格天然石头的状态为 `1 → 远端挖掘后 0 → 区块卸载重载后 1`，本地账本没有该坐标。
- **建议：** 将远端修改记入本地账本，依靠已有 `_applyingRemote` 守卫阻止回环上报。
- **回归重点：** 远端放置、挖掘及覆盖本地旧修改后，卸载重载仍与服务端一致，且不产生回环消息。

### B32-3：异维度断线重连后，两端维度不一致（P1）

- **位置：** `src/net/NetworkManager.js:91`，重连分支；`server/room.js:274`，`addPlayer()`。
- **原因：** 重连只发送房间名；服务端将新连接玩家设为主世界，客户端却保留原来的下界或末地世界，没有恢复维度的握手。
- **影响：** 客户端仍在下界操作，服务端却将方块修改记入主世界；玩家可见性和掉落物同步也会错位。
- **验证：** 模拟重连仅产生 `hello`、`join_room`，客户端世界维度和网络层维度均仍为 `nether`；服务端入房逻辑明确将玩家维度重置为主世界。未进行真实断网端到端验证。
- **建议：** 重连时先完成维度与账本同步，再恢复交互，明确服务端与客户端维度恢复的顺序。
- **回归重点：** 在非主世界断线重连后，两端维度、位置、玩家可见性和方块落账维度一致。

### B32-4：背压回放可能把旧维度数据发送到新维度（P1）

- **位置：** `server/room.js:435`，`replayBlocks()`。
- **原因：** 回放开始时捕获旧维度账本，但每批发送使用当前 `player.dim`。背压等待期间换维度后，数据来源和消息维度不再对应；换房、离线也没有取消检查。
- **实证：** 暂停主世界回放，将玩家维度切换到下界，再恢复发送，得到主世界方块数据配上 `d:"nether"` 的 `block_change_batch`。
- **影响：** 客户端可能把旧维度方块写入新维度；跨房间的未完成回放也缺少生命周期约束。
- **建议：** 固定回放所属房间、维度和会话代次，状态变化时取消旧任务，并检查连接及房间成员身份。
- **回归重点：** 背压等待期间换维度、换房和断线，旧任务不得向新世界继续发送数据。
- **与上一轮关系：** 上一轮新增批量回放需要补齐的时序边界。

### B32-5：潜影盒掉落物回放遗漏内容（P1）

- **位置：** `server/room.js:416`，入房掉落物回放；`onSwitchDimension()` 的掉落物回放及 `onDropTaken()` 的归属锁拒绝补发存在同类遗漏。
- **原因：** 实时生成消息携带 `data`，上述回放和补发路径没有携带该字段。
- **影响：** 后来加入的玩家拾取装有物品的潜影盒时，会得到没有内容数据的盒子；拾取成功后服务端删除掉落记录，造成内容丢失。
- **实证：** 内存服务端账本中存在含物品的 `data`，实际入房回放的 `drop_spawn` 没有该字段。其他两条路径经源码核对确认遗漏。
- **建议：** 统一掉落物消息的序列化出口，保证生成、回放和拒绝补发使用完整的同一数据契约。
- **回归重点：** 带内容潜影盒经过入房、换维、拒绝补发后，内容逐槽一致，最终拾取不丢失。

### B32-6：联机终局状态污染后续单机存档（P1）

- **位置：** `src/player/Game.js:304`；`returnToMenu()` 未清空 `finaleInfo`。
- **原因：** `finaleInfo` 接收联机房间状态，返回菜单时没有清空；之后任何 `start()` 都会应用它，包括单机新建和加载。
- **实证：** 在 Game 假环境中设置已通关联机房间的缓存状态，返回菜单后新建单机世界，新世界出现 `finaleDone=true`，并继承旧祭坛坐标。
- **影响：** 无关单机存档被错误标记为已完成终局；后续保存可能将污染状态持久化。
- **建议：** 将缓存限定于对应联机会话，退出时清理；单机启动只读取自身存档。
- **回归重点：** 已通关联机房间退出后，新建和加载未通关单机存档均不得继承终局状态或祭坛坐标。

## 二、中优先级

### B32-7：换维度清空床重生点（P2）

- **位置：** `src/player/Game.js:2110`，`_composeSwitchLoadData()`；`src/player/Game.js:466`，启动恢复逻辑。
- **原因：** 换维快照没有携带 `bedSpawn`，而 `start()` 在缺字段时将其设为 `null`。
- **影响：** 设置床重生点后前往其他维度，再回到原维度死亡，原床重生点已经失效。
- **实证：** 设置有效床重生点后，调用真实快照合成方法，返回对象缺少 `bedSpawn`；启动清空行为由调用链确认。
- **建议：** 换维快照保留带维度信息的床重生点。
- **回归重点：** 床重生点经过换维往返及保存加载后保留，床被破坏时仍按现有逻辑失效。

### B32-8：世界销毁遗漏共享材质和图集纹理（P2）

- **位置：** `src/player/Game.js:196`，`_disposeWorld()`；`src/render/ChunkMesh.js:84`，builder 材质创建；`src/render/SVGTextures.js`，图集创建。
- **原因：** 每次启动创建新的 builder 材质和图集纹理，销毁世界时只释放区块 geometry，没有释放 builder 的三种材质和图集。
- **实证：** 在 Game 假环境中监听三个材质及图集的 `dispose` 事件，退出世界后四个计数全部为 `0`。
- **影响：** 重复进入世界或换维度存在 GPU 资源累积风险。实际 GPU 累积量尚未通过真实浏览器测量。
- **建议：** 明确 builder 资源所有权并统一释放；跨世界缓存纹理应保留独立生命周期，避免误释放共享资源。
- **回归重点：** 重复启动和退出时，旧 builder 材质、图集各释放一次；浏览器侧观察纹理和程序资源是否稳定。
